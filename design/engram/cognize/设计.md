# cognize

[← 设计索引](../../INDEX.md) · [Engram](../设计.md) · 实现：[`mh/engram/cognize/`](../../../mh/engram/cognize)

cognize 在会话树上建立跨分支的快捷节点：同一件事、同一个对象或一类东西跨了线、工作区和日子时，给它一个有身份、可追溯的表述。沿一条线就能看全的事不必再建 C。

**C 是自我的特质**：“我”怎样对待事，即从经历里长出来的世界观细则、方法论、行为准则、冲突的解法，不是事的地图。事的结构由话题、线和骨架给，跨会话的同一点由 form 之上的推演给。

**当前只有数据结构、引用、查询和确认等程序接口，第一批 C 由主会话手写；视角里会话结构已经由 form 的一步产出，命名演进还没接进写入，自动生成 C、睡眠整理和 Synapse 上的 C 导航尚未接入。** 以下分别说明已定结构与后续过程。

## 认识的边界

observe 留下原文支持的观察，form 整理会话结构，cognize 才从经历中归纳未明说的原因与经验。归纳出来的理由先是候选，不能回写成“用户当时明确说过”。

C 的全貌是一条新认识，不吞掉下面的陈述、事件和原话，从 C 总能走回每一条陈述、事件，直到原话。Atlas 入口只是 C 的一个面：按事做地图的那部分由线和骨架接走，留下的是准则视角的入口；构建归 cognize，Synapse 负责读取和导航。

- **抽象 C（暂名“理”）是一条条准则**：手记扉页里记下的那些就是。
- **具体 C（暂名“事”）是准则的实际案例**：一件件实实在在发生过的完整事件，既是警醒，也是佐证。
- **二者不是非此即彼**，是看同一个问题的两种视角：准则从案例里长出来，案例因为准则才被记成一件事。
- **自相似**：抽象 C 之于具体 C，就像线之于陈述——线串起陈述，准则串起案例。
- **规模天然小**：很久以后也只设想有百余条。平时不加载，由联想按输入查出相关的几条注入；扉页是常驻的那几条。
- **不是每件事都要形成 C**：会话是天然的认知结构，会话内的关系 form 已经完成；具体 C 是成了某条准则的案例的那件事，出了会话的合并才归 cognize。
- 手记扉页、仓库协作规则里的做事准则、助手在宿主自动记忆里记下的偏好，是已有的手写 C，也是第一批实物参照。

## 先长出来的是视角

C 长出来的实物先是**挂在陈述上的视角**，不是“节点结构”里那种带成员的节点。一个视角是看陈述的一个切口——一段会话里的问题与决定、叫法，等等；每个切口由一个独立的标注者负责：写入时判一次，挂在陈述上，不改陈述；读的时候按问题组合视角，陈述因此可以写得精简。现在认下来两个：

- **会话结构**：一段会话里的问题与决定，判断带“因为”。判断的原因在会话之内就归纳得出，所以它作为 form 的产物挂载，是 form 与 cognize 之间的一层。
- **命名演进**：叫法的网——改名、别名、拆分合并、撤销，各带出处。

视角是世界观（自相似）下自然的东西：用视角定义认识、用认识定义视角都自然。视角有方向：从上往下导航，会把图收缩成树、要靠程序聚类，那是在 C 的位置上重做线和骨架的活；从下往上标注，才是切口。两种方向都成立，只是位置不同——在架构的尺度上，像盲人一旦能看，鼻和腿就统一成象；在工程的尺度上是换了方向。由模型来写带成员的节点先不做，等视角之上出现一件需要跨视角、有身份的事时再看；主会话里当面认下的准则直接写成节点（下一节）。

## 怎样长出一个 C

第一批 C 不由模型生成，是在主会话里、用户在场时，把一条已经手写下来的教训认成 C，出生就是已验证的。

- **顺序**：念头在先，案例来改它。手里先有一条教训（层级暧昧的正合适）；带着它到记录里找事，事会改写理（一条独立的教训可能变成更上一层的理下面的一件事）；措辞在场定；理和事不先判，成员是陈述的是事，成员是 C 的是理，一件事挂几条理等第二个 C 时自己出现。
- **什么时候长**：不设节拍、不留待办、不计数，搭在本来就发生的事上：被用户纠正、写下一条案例里“事后看清的”、例行探索里出现“和某项同一类”。这时回忆一次相似的，是“又一次”就在对话里提，用户接就当场认。理至少要两件事，所以 C 出生在“又一次”上。
- **每一个注意什么**：至少两件事，尺度或场合不同更好；每句走得回陈述，入库前到记录里核一次；看有没有再犯，手写规则接得住的不急着认；事的那一句写“在这里落成了什么样”，不复述理，所以事单独成节点；理的表述里写“何时”（该想起它的动作，每个时刻从一件事里来）和“何时不用、换成什么”（它的边界），都是带引用的句子，不加字段。

## 怎样用：让认知成为行为方式

模型学到的都在身外，一条认知要起作用得过两关：想到要取，取来读进去。难的是第一关，而该想起的时刻多半在助手自己的动作里，不在用户的话里。所以 C 按“何时用”组织，不按主题。三种落法，按冷热流动：

| 落法 | 是什么 | 适合 |
|---|---|---|
| 常驻 | 扉页或协作规则里的一行 | 极少数、处处用得上的 |
| 按需载入 | 按任务性质判出此刻该重点用哪几条，载入主会话：最贴近眼前尺度的那件事加一行理；主会话也能自己去取 | 大多数 C |
| 沉进结构 | 变成程序、格式、检查或例行方法，不再靠想起 | 反复再犯的 |

流动靠再犯：再犯一次往热处挪或往下沉，很久没碰到就退回只在被问到时讲得出；模型没有疼，再犯是工程上补的疼。沉下去的 C 不消失，留作那个结构的来历。提醒本身不够：记了“要小心”照样再犯，换成本身不会错的做法才停。按需载入的方向是判决载入（尚未实现）：节律起一个足够强、和主会话不同的模型，靠一套一目十行的读法判出此刻该重点采用哪几套认知，按任务性质自动载入，“何时”“何时不用”是它读的材料。连带一个评判：主会话自己采用的 C 和判出的 C 一致，说明这条 C 写得合各类模型的口味，不代表它说得对，用对用错要另外留意；不一致，这条 C 要细化或再想想对不对。两边要先独立（先影子、只判不送），一致才有意义。

长期追求：在不同情形下用更合适的认知方式，方式不奏效时知道切换。先做得了的是后半句：失败留痕迹（调到第几轮、转折几次、被纠正几次），程序数得出；事先选对方式是切换的事攒出来的结果，不给认知方式列分类表。每次切换当一件事记，没有事不立理。

## 节点结构

| 内容 | 含义 |
|---|---|
| 具体 / 抽象 | 具体：一件完整的事，准则的一个案例；抽象：一条准则，成员是它的具体 C，也可以是别的抽象 C。两者结构相同，C 之间嵌套、一件事挂几条准则都是自然结果。宁窄勿宽 |
| 名字、别名 | 可以按名字查找；现状中大小写归一后不重名 |
| 表述 | 短而自足的句子列表，每句带引用 |
| 成员 | 陈述、话题、线、骨架或其他 C；旧 J 只作历史兜底 |
| 成员关系 | `part`：整体到部分；`instance`：类到实例 |
| `from` | 前驱；空是新生，一个是接替，多个可表达合并 |
| 状态与窗口 | 进行中、搁置、结束，以及该 C 的时间尺度 |

节点不可变，更新写后继；未被后继指向的节点是现状，身份从 `from` 链推导。多个前驱的数据结构已经支持，在线自动形成如何合并尚未定型。

## 候选与已验证

- cognize 写出的 C 是候选。
- 主会话与用户确认后写一个后继，指向候选，可以同时修改名字、表述和成员。
- 人工核对的骨架视为已验证结构，留在骨架原处，不复制到 cognition 表。
- 后来自动产生的后继仍是候选，直到再次确认。

状态从出生的 act 推导，不另设可随意切换的布尔字段。“已验证”表示有主会话确认来源，不构成对世界事实永远正确的保证。

## 引用：身份与钉住的版本

C 既要知道“这是哪个东西”，又要保存“写下时看的是哪一版”。

| 对象 | 身份 | 钉住的版本 |
|---|---|---|
| 陈述 | 来源、会话、S 序号 | 对应 form_record 编号 |
| 话题 | 来源、会话 | session_entry 编号 |
| 线 | `from` 链 | topic_line 编号 |
| 骨架 | 工作区、节点路径 | 采用骨架的版本 |
| C | `from` 链 | cognition 编号 |
| 旧 J | 固定 J 编号 | 同一编号 |

只存行号会丢掉跨版本身份，只读最新版会抹去当时依据。程序接口 `pin` 固定引用，`resolves` 检查版本与身份，`now` 找现行版本，`fresh` 比较是否变化。

下一级变动时，设计要求等 C 被用到再提示直接上一级，由上一级决定是否改写。引用接口已经存在，完整的认知修订调度仍待接入。

## 后续过程

计划先用来源、名字、索引词、文件和共同访问足迹给候选，再由模型决定新建或接替，写名字、表述与成员。每次调用保存 act，程序分组作为缓存。

在线侧重增量新建和接替；睡眠侧重抽象、合并和地图重建。先做的是视角的标注者；带成员的节点等视角之上出现一件需要跨视角、有身份的事时再看。具体 C 如何认出“跨线的同一件事”、抽象 C 如何生成、哪些候选送去讨论，以及足迹如何参与，仍需实际案例验证。

**抽象 C 是不是一个视角**，只有一个样本（第一个 C 里，事要有自己的一句话，标注放不下，所以写成了节点），不定：一条准则是一个跨会话的切口，它的案例（具体 C）就是被这个切口标注的事。成立的话，成员关系可以写成标注，节点形的 C 不必单独造。

还没定的：多对多的边（一件事挂几条准则、准则挂在准则下）现在写在上级的成员里，加一个案例就要给准则写新版本；倾向照挂线另开只追加的边表，边挂在身份上，撤回也追加。给 form 的视野也没定：form 需要 C 的视野才能更好地起名、写索引词，现在只有骨架，候选 C 怎样给、给多少（像起名查重那样只附命中的），等有了真实的 C 再定。

结构不宜过早封闭成固定类别，以免只能形成预先允许的认识。反馈原则同 Engram：内容齐全时写后继，不齐全才发申请；C 的统一反馈工具尚未接入。
