# cognize

[← 设计索引](../../INDEX.md) · [Engram](../设计.md) · 实现：[`mh/engram/cognize/`](../../../mh/engram/cognize)

cognize 在会话树上建立跨分支的快捷节点：同一件事、同一个对象或一类东西跨了线、工作区和日子时，给它一个有身份、可追溯的表述。沿一条线就能看全的事不必再建 C。

**当前只有数据结构、引用、查询和确认等程序接口，自动生成 C、睡眠整理和 Synapse 上的 C 导航尚未接入。** 以下分别说明已定结构与后续过程。

## 认识的边界

observe 留下原文支持的观察，form 整理会话结构，cognize 才从经历中归纳未明说的原因与经验。归纳出来的理由先是候选，不能回写成“用户当时明确说过”。

Atlas 的节点就是 C；Atlas 的构建归 cognize，Synapse 负责读取和导航。C 的全貌是一条新认识，不吞掉下面的陈述、事件和原话。

## 节点结构

| 内容 | 含义 |
|---|---|
| 具体 / 抽象 | 一件事、一个对象，或一类东西 |
| 名字、别名 | 可以按名字查找；现状中大小写归一后不重名 |
| 表述 | 短而自足的句子列表，每句带引用 |
| 成员 | 陈述、话题、线、骨架或其他 C；旧 J 只作历史兜底 |
| 成员关系 | `part`：整体到部分；`instance`：类到实例 |
| `from` | 前驱；空是新生，一个是接替，多个可表达合并 |
| 状态与窗口 | 进行中、搁置、结束，以及该 C 的时间尺度 |

节点不可变，更新写后继；未被后继指向的节点是现状，身份从 `from` 链推导。多个前驱的数据结构已经支持，在线自动形成如何合并尚未定型。

## 候选与已验证

- cognize 写出的 C 是候选。
- 主会话与用户确认后写一个后继，指向候选，可以同时修改名字、表述和成员。
- 人工核对的骨架视为已验证结构，留在骨架原处，不复制到 cognition 表。
- 后来自动产生的后继仍是候选，直到再次确认。

状态从出生的 act 推导，不另设可随意切换的布尔字段。“已验证”表示有主会话确认来源，不构成对世界事实永远正确的保证。

## 引用：身份与钉住的版本

C 既要知道“这是哪个东西”，又要保存“写下时看的是哪一版”。

| 对象 | 身份 | 钉住的版本 |
|---|---|---|
| 陈述 | 来源、会话、S 序号 | 对应 form_record 编号 |
| 话题 | 来源、会话 | session_entry 编号 |
| 线 | `from` 链 | topic_line 编号 |
| 骨架 | 工作区、节点路径 | 采用骨架的版本 |
| C | `from` 链 | cognition 编号 |
| 旧 J | 固定 J 编号 | 同一编号 |

只存行号会丢掉跨版本身份，只读最新版会抹去当时依据。程序接口 `pin` 固定引用，`resolves` 检查版本与身份，`now` 找现行版本，`fresh` 比较是否变化。

下一级变动时，设计要求等 C 被用到再提示直接上一级，由上一级决定是否改写。引用接口已经存在，完整的认知修订调度仍待接入。

## 后续过程

计划先用来源、名字、索引词、文件和共同访问足迹给候选，再由模型决定新建或接替，写名字、表述与成员。每次调用保存 act，程序分组作为缓存。

在线侧重增量新建和接替；睡眠侧重抽象、合并和地图重建。具体 C 如何认出“跨线的同一件事”、抽象 C 如何生成、哪些候选送去讨论，以及足迹如何参与，仍需实际案例验证。

结构不宜过早封闭成固定类别，以免只能形成预先允许的认识。反馈原则同 Engram：内容齐全时写后继，不齐全才发申请；C 的统一反馈工具尚未接入。
