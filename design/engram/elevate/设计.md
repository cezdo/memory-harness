# elevate（内核态，`/mhcore`）

[← Engram](../设计.md) · 实现：[`mh/engram/elevate/`](../../../mh/engram/elevate)

内核 `core.md` 是手记的扉页：不能从别处重算、要可追溯，是 Engram 的正本，和 `engram.db`、对话原始记录并列。`/mhcore` 是人放行的写，守住这份正本的门，所以归 Engram；扉页的渲染留在 Synapse 的[手记](../../synapse/设计.md#手记)，一个守、一个读。

内核默认只读，叫用户态；用户用命令临时提权，这一轮叫内核态（像 sudo 一样，内核态的改动要有系统日志）。LLM 没有特权级，写在推送里的“改这份要用户审定”对模型只是建议，所以特权落在写入路径上，由钩子认，提权只能由人做。

S：用户整句以 `/mhcore` 开头的输入（提权），以及编辑类工具调用前后（拦、记）。R：在不在窗口里、目标是不是 core.md。P：拒绝或放行，记内核日志。

- **提权**：整条消息以 `/mhcore` 开头（Codex 写 `$mhcore`），后面跟要求，如 `/mhcore 把扉页里的称呼改成某某`。UserPromptSubmit 钩子从用户原话里认出来，给这个会话开一个窗口，在内核日志里记一条提权（带原话），再补一句上下文（这一轮是内核态、源文件在哪）；这次输入不拦，要求照常交给模型。讨论里提到 `/mhcore` 不算；只打 `/mhcore` 没有要求的，拦下并回用法。
- **窗口**：这一轮结束（Stop）就关；下一次输入、超过 30 分钟也关（Stop 丢了的兜底）。
- **拦**：PreToolUse 看编辑类工具（Claude Code 的 Edit、Write、MultiEdit、NotebookEdit，Codex 的 apply_patch），目标是 core.md、又不在窗口里，就拒绝并回一句：用户态下只读，要改请用户用 `/mhcore`。Bash 这类命令不解析，交给下一条兜底。
- **记**：PostToolUse 在每次工具调用后比对源文件和数据目录里的快照（`kernel/last.md`）；变了就记一条改动（改前改后的 diff），在窗口里记成 `edit`，不在窗口里记成 `unlogged`。Bash 改的、用户在编辑器里手改的、别的宿主改的，都在下一次任何一个会话调工具时被发现；改的人不知道，顶层不写宿主、会话，发现它的宿主、会话、工具记在 `found_by`，免得读成发现者改的。没有快照时先记一份基线。
- **内核日志**：数据目录的 `kernel-log.jsonl`，只追加，程序写：时间、种类（`grant`、`edit`、`unlogged`、`close`、`baseline`）、宿主、会话、工作目录，提权的原话，改动的 diff 和前后哈希。
- **读内核日志**：原件一条一段 JSON，大半是 diff 和哈希，模型读起来费；读的时候照 dmesg 排成一条一行（`python3 -m mh.engram.elevate log [-l 级别] [编号]`），前缀固定：编号（行号）、本地时刻、级别、谁、种类、会话、摘要。级别：`unlogged` 是 warn（窗口外改了内核，只有它要人看），`grant`、`edit` 是 notice，`baseline`、`close` 是 info。谁：提权是用户，窗口里的改动是“我”，其余是程序（窗口外的改动不知道是谁改的，会话写发现它的那个）。连着的同类（种类、宿主、会话都一样）折成一行，写 ×N 和编号区间；diff 按编号展开。手记近况只列内核所在仓库近 3 天的 warn，没有就不出声。
- **不进库**：提权那句 `/mhcore` 本来就是宿主会话里的一轮；窗口里的改动是那一轮的工具调用，改了什么在 git 里。日志里库没有的只有程序看到的（窗口外的改动、基线、关窗），先只给读法。
- **钩子出错不挡宿主**：放行，错误记进 `events/kernel-errors.log`；漏拦的改动由 PostToolUse 的比对兜住。

这是工具路径上的约束和审计，不是文件系统权限隔离。命令和 skill 的源文件在 [`mh/skills/mhcore/`](../../../mh/skills/mhcore)，装进 Claude Code、Codex，先预览再执行：

```sh
python3 -m mh.engram.elevate
python3 -m mh.engram.elevate --apply
```

**还没做**（等真实案例）：dsh 的插件命令；口令（口令单独一条、钩子核对哈希后拦下，不进原文和上下文）；二次确认；回滚（现在靠 git 和日志里的 diff）；开机时列出内核最近的改动。
