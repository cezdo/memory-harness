# 采集

[← 设计索引](../../INDEX.md) · [observe](设计.md) · 实现：[`collect.py`](../../../mh/engram/observe/collect.py)、[`sources/`](../../../mh/engram/observe/sources)

采集把宿主会话和显式指定的 ChatGPT 导出归一化为轮次，保留原文并写入私有数据库。整个步骤由程序完成，不调用模型。

采集是适配层：每种来源一个解析器；新宿主、群聊，以后和现实世界交互的传感器，都从加一个来源开始。轮次是现在几个宿主共有的单位，不是不变量：来源的形态装不进轮次时，改单位、舍弃旧概念，不硬套。

## 轮次与来源

- 一轮对应一次输入及随后到本轮结束为止的输出。最终回答、中途叙述、可读推理和工具名分别保存。
- 每轮保留宿主原始文件的地址，标明来源是人、宿主注入还是脚本，以及是否结束。
- 逐轮模型：`turn_detail.models` 按输出先后记本轮用到的模型，连续相同的只记一次，不进内容哈希。Claude Code 从助手消息取，Codex 从当轮上下文、设置和输出取，dsh 从请求上下文、模型选择取，ChatGPT 从消息的模型字段取。不从会话最后的模型倒推；来源没给时为空，观察输入标未知。旧轮次只在原文哈希与位置一致、模型记录为空时补上；已有记录不同则报告、不覆盖。
- 未完成的末轮留到下次采集；结束标记由宿主解析器识别，不能用文件暂时没变化代替。
- 只采主会话：解析器认得出 `user`（人直接参与）、`subagent`、`review`（自动审查）三种会话，只有 `user` 入库，另两种文件照样记下处理过、不再解析。观察和形成本来也只读主会话，子代理和审查进了库没有读的一方；宿主的原文件还在，要查去翻原件。 不是对话的宿主调用也不入库：宿主给会话起标题另起的一次调用记成 `title`，主配置目录里的无头调用（如 `claude -p`）记成 `headless`。
- 别的会话发来的消息不成轮。宿主把它写成用户输入的一段，形如“另一段会话发来消息”加正文。它不是用户的话：解析时记在轮次旁边（谁、正文），夹在一轮中间的记这一轮，落在两轮之间的记前一轮并说明在轮后，“我”接着的回答记在那轮回答的最后。这类记录只往后添、已有的不改，早先入库的行由采集补上；读的时候只读库，不回原文件（原文件不保证一直在）。
- 目标模式另有一种切法。用户设的目标记在单独的事件里，宿主每次开工发一段包在内部标签里的“继续朝目标做”。目标设下（或改了）之后的第一次开工才算一轮，用户的话就是那个目标；之后的续接是宿主的，不起新的一轮，回答接在原来那一轮里；只改状态（完成、暂停）不算新目标。以前把整块标签当宿主注入丢掉，目标模式的会话一轮都解析不出来。

后台通知、命令回显、压缩总结等保留原有切轮位置，由观察阶段另作标注和折叠。已经入库的轮次不能因更改切法而改变序号含义。

## 增量与去重

轮次按内容哈希去重；相同原文出现在 fork 或迁移副本中时，各位置保留发生记录，原文不重复观察。文件大小、修改时间和采集解析版本都没变就跳过；解析版本更新后重新核对旧文件、补可更正的字段，不重写原文；ChatGPT 导出配置的工作目录变了同样重新核对。记的是解析之前的大小和时间，解析期间又写进的下次照样再读。单文件解析失败不影响其他文件。

当前对新会话设有 30 分钟等待窗口，便于未使用的测试会话在采集前清理；无法识别开始时间的会话照常处理。该窗口不是删除或隐私保护承诺。

已入库的位置只做从无到有的更正：解析器先前没认出的才补——来源已结束而库内还没标记，把结束标记补上；分叉点、非正常结束、别的会话发来的消息只补没记的；新认出的宿主注入和脚本（如重启后的续接提示）从“人”改过来，只从“人”改出去。位置对得上但轮次不同的，列出来、不写；同一位置内容不同的，也列出异常、不覆盖原文。这是更正误读，不是改写原文。

不接 mh 的会话不收：实例配置 `[connect].unplugged` 对上的会话（按 cwd，规则见[词典“`[connect]`”](../../global/词典.md)）一轮都不收；整个文件都是这样的会话时不记成处理过，从名单里拿掉后下一轮照常补采（文件还在的话）。`mh unplug` 起的测试宿主，会话写在数据目录的 `<宿主>-unplugged-home` 里，采集不枚举那里（见 [Synapse“不接 mh”](../../synapse/设计.md#不接-mh)）。

## ChatGPT 静态导出

实例配置 `[observe].chatgpt_exports` 显式列出 `{file, cwd}`：`file` 是原始会话对象数组（完整导出中的 conversations JSON，或从中筛出的子集），`cwd` 是内容所属的工作目录。不扫描整个导出目录，不按 ChatGPT 的项目标签猜工作区，只导入已筛选并配置的文件；建议先在库的副本上核对，再逐批加文件。

- 每个 conversation ID 是一个来源会话，沿 `current_node` 的 parent 链还原活动分支，不按时间戳排序。断链、环、重复 ID 和未适配的消息形状报错，不悄悄收半段。旁路分支保留在原始 JSON 中，不自动展开；不同会话的共同前缀复用已有的内容去重和分叉处理。
- 每条 user 消息起一轮；最后一条非空助手正文作回答，之前的正文作中途叙述，可读的思考摘要存为推理。后面已有下一次用户输入的轮次算结束；末轮有正文才收。快照没有运行时的结束标记，观察输入写明这种取法，不声称正常完成。
- 地址保留 conversation ID、节点 ID、message ID、附件元数据和原始消息的模型字段。附件正文和工具执行记录缺失时写明来源限制，不补写内容，也不从引用链接臆造工具名。
- 新来源走普通的新原文队列，不申请再观察。反复采集不产生重复轮次。

导入的网页端讨论回答长、复述和解释多，按一个明确的视角读：实例配置 `[engram].views` 写“来源 → 视角”，视角进 Operator。会话读完以后，observe 把还没筛过的 E 连同每轮用户的原话交给模型（[`select.py`](../../../mh/engram/observe/select.py)，提示词 `select-view-v0.1`），模型列出从这个视角看不留的，程序写一条收回（`prune`）；出处里有用户原话的程序保底留下。有没筛过的 E 的会话，form 先不整理；整理时 pack 提示词末尾接上视角要求（`pack-view-v0.1`），陈述更精简。要换一个第一轮没照顾到的视角，就带着新视角从原文重新观察，不从旧结果里筛。

## 观察开关

观察开关也是用户的表达。宿主钩子拦下命令后，会话文件可能没有这次输入，因此钩子追加的 `observe-switch.jsonl` 作为独立采集来源，保存命令、宿主会话和原始位置。开关不经过模型，也不等待新会话窗口。Synapse 的联想开关（`souhatsu-switch.jsonl`）和 yorimichi（`yorimichi.jsonl`，助手调 MCP 工具记下的条数和理由）在宿主的会话文件里同样没有原话，按同一个来源收：每个宿主会话、每种记录各成一个会话；yorimichi 的来源是主会话，不是人。

## 聊天的原文

`mh listen`（[`listen.py`](../../../mh/engram/observe/listen.py)，常驻）连 QQ 协议端的 OneBot 11 正向 WebSocket，事件原样追加进数据目录的 `listen-onebot.jsonl`（收到的时刻和原样的事件；心跳、接口回执不记）。实例配置 `[listen]` 可以只记指定的群和私聊；协议端在别的机器上时，由它自己起 ssh 隧道。这份文件是聊天唯一的原始记录；采集还没读它，作为来源怎么切轮等真实记录攒够再定。

关闭观察作用于 observe 全流程，不等同于关闭原文采集或删除已存内容。已交给 form 的 E 撤下或恢复时会留下边界记录，见[修正机制](../申请.md)。

## 隔离

观察者与实验调用使用独立目录，产出的宿主会话不放进正常采集路径，避免系统把自己的整理结果反复采回。测试使用合成材料与临时实例，不改运行中的数据。

## 使用

```sh
mh collect
```

这会读取本机宿主会话并将原文保存到当前实例，执行前确认数据目录。原文可能含凭据，数据库和生成的阅读页应私有保存。配置与隔离实例的做法见[使用说明](../../global/使用.md)。

观察开关适配在 [`switch/`](../../../mh/engram/observe/switch/)，需显式加载到各宿主；关闭观察不等于停止采集。
