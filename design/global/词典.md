# 词典

[← 设计索引](../INDEX.md)

这里解释当前设计中的术语。词头按原项目格式维护：`/` 连接同一东西的不同叫法，全名在前；不同事物分别成条。源码运行时可读取这些词头补充术语别名；个人名字、别名和工作区映射仍从私有实例配置读取。

## 总体与模块

**Memory Harness / mh**

套在助手外面的记忆基础设施；`mh` 是代码包与命令名。

**总体设计 / global**

全局目标、不变量、分工、词典与通用安装配置。

**Engram / engram**

写的一侧，保存原话、观察、形成与认知的历史。

**observe / 观察**

从原话写出 event。

**form / 形成**

从 event 整理会话记录、话题与线。

**cognize / 认知形成**

从会话结构提出跨分支的 cognition；自动形成尚未接入。

**Synapse / synapse**

读的一侧，负责推送、拉取、导航与 use 足迹。

**rhythm / 节律**

调度过程的运行时机、并发与额度。展示自己的窗口与照看也归在这一层。

**表达 / express**

写入与读取共用的人称、来源视角与呈现规则。

**公开发布 / release**

公开材料选择、打包资源、清单与同步边界。

**回复 / reply；叫到、这一段**

`mh reply`：助手在 QQ 群里被叫到时回几句（[reply](../reply/设计.md)）。叫到：@ 助手、回复助手的消息、文字里有助手的名字。这一段：按每天固定时刻和长时间无人说话切出的那一段聊天，是回复的上下文。

**不静默**

三条不变量底下的那一条：运动是绝对的，发生是不可撤销的。删除、有损保留、换切法、改理解都允许，各自留下“发生过”的记录（[总体设计](设计.md#三条不变量)）。

**底线（mh 结构的）**

断了 mh 就退出的几条结构：后继另起名字，mh 的记录作为它的原始来源（[总体设计](设计.md#底线与退出)）。其余是条件到了就变的形态。

**资源边界；余力**

资源边界是“我”能调用的资源分成的三档：按需调用、要用户同意、不碰。每一档带条件、随授权移动，每次移动显式记下来源。余力是按需的资源现在还剩多少（占用、额度、上下文）。两个轴分开看：先判档，再看余力。这是“我”身体的那一面，方向，还没实现。

## 数据与交互

**宿主**

承载助手的环境，目前内置 Claude Code、Codex、dsh 适配。

**用户 / user**

与助手交互的角色；面向本人写的文字按读者使用“你”，模型自称“我”。

**工作区**

会话所属的项目，由实例映射、会话更正和目录信息确定。

**Occurrence**

实际发生过的一次表达、认知行为或读取；时间属于它。

**绝对时间**

存、比较、切出“一天”都用绝对时间，只在显示的一端按读的人所在时区换算：页面按看页面的浏览器，手记、状态页和日志按本机现在的时区，常驻进程每轮现读，不停在启动时读到的那一份。外面来的时刻先换成绝对的再用（[总体设计](设计.md#按时间回放)）。

**Claim**

被表达的内容；存在不等于真实、被认可或已验证。

**Operator**

一套做法：模型、提示词、隔离方式、窗口与影响输入的参数。

**act**

一次认知行为，保存实际输入、原始输出、原因、成本和错误。

**event / E**

observe 从一轮或多轮原话中写出的观察。

**judgment / J**

form 的判断；当前常驻流程主要做挂线等结构判断。旧版逐句 J 保留历史，新的跨会话推演尚未接入。

**cognition / C**

自我的特质：抽象 C（暂名“理”）是一条条准则（世界观细则、方法论、行为准则、冲突的解法，手记扉页里的就是），具体 C（暂名“事”）是准则的实际案例，一件完整发生过的事，既是警醒也是佐证。两者是看同一问题的两种视角，抽象 C 之于具体 C 如话题线之于陈述。平时不加载，由联想按输入注入；扉页是常驻的那几条。事的地图由线和骨架给，不由 C 给；当前已有程序接口。先长出来的实物是挂在陈述上的视角（见**视角**），带成员的节点形还没做。

**会话记录**

按会话先后整理的陈述，引用来源 E。

**陈述 / S**

会话记录中的一条内容，S 序号在话题内定位。

**参与方 / aside**

一个会话里开口的对象：用户本人、“我”、别的会话发来的消息、宿主注入（通知、打断、命令、压缩、重启续接）、脚本。别的会话发来的消息不是用户的话，也不单独成轮：采集时由程序认出，记在那一轮的 asides 里（谁、正文，连同“我”接着的回答），观察时写明是谁发来的。

**归纳 / induce；标准陈述、降半级**

归纳是 pack 之后的一步，把一段会话里讲同一串事的几条陈述概括成一条新陈述（现在只做排查）。被归纳的陈述降半级：不在主列里，挂在归纳陈述下，句柄不变、可以直达。归纳得到的和没被归纳的陈述都是标准陈述（[form](../engram/form/设计.md#归纳陈述之上的陈述)）。

**会话结构 / structure**

form 挂线之后的一步：把一个话题的陈述整理成“问题—决定”，节点是问题、方向、证据、判断、遗留，边是它们之间的关系，节点指回陈述。陈述超过一页时才做；relive 先给结构，再让读的人展开陈述。

**会话入口 / 话题 / T**

会话记录的入口，包含名字、主题、停在与索引词。

**停在**

会话结束时定下、完成或仍悬而未决的内容。

**话题线 / 线 / L**

为检索组织若干会话入口的结构；相关目标要能解释为什么往这里找。

**挂线 / attach**

把入口放到线上的结构判断，作为可反馈修正的初值。

**骨架**

人工核对过的目录或文件层级；为 form 提供结构参照。当前指目录设计加词典：目录说有哪些部分、怎么分层，词典说每个部分里的东西叫什么、指什么、为什么这么叫；源码运行时从 `design/` 下含 `设计.md` 的目录生成（[form](../engram/form/设计.md#骨架)）。从挂线所用的层级展开成目录设计加词典，是同一个东西的词义演进，不算撞名。

**Atlas**

认知及形成认知的方法；设计中节点是 C，当前导航主要沿骨架、线、话题展开。

**视角 / 参考系**

把 Atlas 的图收缩成树的一种方式；“参考系”和“视角”是同一件事的两种叫法。现在也是认知先长出来的实物：看陈述的一个切口，由独立的标注者负责，写入时判一次、挂在陈述上，不改陈述；读的时候按问题组合视角，陈述因此可以写得精简。现有会话结构、命名演进两个。旧的主题、对象、时间等视角随旧实现撤下，当前地图走骨架、线、话题，不等于它们已经重建。

**命名演进**

叫法的网：节点是名字，边是改名、别名、拆分合并、撤销，带出处和生效时间。写入时判一次，读的人不用再分新旧。是一个视角，方案还没定。

**View**

选用哪些来源版本的读视图；更新视图不抹去其他版本。

**use**

一次推送、拉取、导航或相应反馈的发生记录；保留目的、版本和实际返回文本。

**监听 / listen**

`mh listen` 连 QQ 协议端，把事件原样追加进数据目录的 `listen-onebot.jsonl`，是聊天唯一的原始记录；只收不发。

**`/no-souhatsu`、`/do-souhatsu`（联想开关）**

用户在会话里输入的一对命令：关掉或恢复这个会话的联想，最后一次说了算，默认开。不调用模型，由联想的钩子认出、记下、拦下。

**yorimichi / 寄り道（联想能拐几次）**

一段对话现在允许联想拐几次，由助手在对话阶段变了时用 MCP 工具 `yorimichi` 记：平常是 1；0 不给联想，只在收窄到一被打断就容易出错的一件事时用，在干活本身不算；聊开了、话题在散是 2–3。是会话的状态，不是每轮的判断；用户的联想开关优先于它。

**曝光**

足迹记下给到了什么内容；不等于读懂或用上。

**在场**

写回复时某条记忆仍在上下文中；当前部分分析仍按曝光近似。

**有回应**

后续拉取、显式引用或复述等可观察行为。

**申请 / request**

请求某一层重做或修订；与已经写出正确内容的反馈分开。给 form 的申请带级别（陈述、入口、挂线、单位），一级的问题不越到下一级，只重做那一级的步骤。

**手记**

会话接入时送入的一份上下文：扉页（内核 `core.md`，也叫内核，几乎不改）、工具说明、近况（项目现状）和当前环境。读了会当作自己相信的经历、记不太住时重读的那份；不用“开场”这类会话开关的说法。

**展示自己的窗口 / show / 此刻的我；看板**

rhythm 下的只读网页，“我”向用户展示自己：此刻、事项、节奏、在哪。读者是用户，和手记（读者是会话开头的“我”）分开。先粗放地放、用着再删；措辞只陈述事实和时间，不催。看板是它现在的一个样子，不是定位。

**照看 / tend**

rhythm 中周期接收状态、处理展示页上要看的事：先由程序判，判不了的交给判定模型，再往执行走。已有的只是接收状态和只读判定，交流与执行还没接入。

**视野 / 作用域**

视野是一层产出时看到的范围（输入），作用域是它写下的东西能覆盖的范围（输出）。借上一层的视野：每一层要产出得好，需要上一层那么大的视野，作用域仍是本层；越不过的部分由上一层自己做。预览之于事件，骨架之于 form；form 的作用域是会话，超出会话的合并归 cognize。

**收回 / 放回（prune / unprune）**

observe 的程序动作：把判为没有必要交给 form 的事件收回，之后可以放回，按先后、后一次说了算，事件本身不删。出处里有用户原话的不收。

**空会话**

宿主里打开了却没开口的主会话：没有一轮是用户的话（命令、宿主注入、脚本不算），也没有“我”的回答。整理循环定期删掉它们的宿主原文件；删之前重新解析原文确认，删掉的留记录。用户说了话、没等到回答的不算（被打断的对话）。

**首屏的展示预算**

一次查询首先给出的有限位置。现阶段不依赖模型主动翻页或选择条数，以固定的一页（6–8 条，按字数定）比较展示效率；同一轮里给过的不再给。

## 命名与句柄

命名上，过程用动词 `observe`、`form`、`cognize`；产物用名词 `event`、`judgment`、`cognition`；Operator 角色用施事名词 `observer`、`former`、`cognizer`。程序标识符使用英文，记录内容使用 UTF-8。ASCII 名分两种：标识符一律小写（模块、目录、命令、MCP 工具、文件名、标签、字段；多个词用连字符，代码和 JSON 字段照 Python 用下划线），展示给人看的名字首字母大写（`[Souhatsu] · Yorimichi 2`），子系统专名（Engram、Synapse、Atlas）行文里首字母大写。

改名和认识一样只取代、不覆盖：词头记现在的名字，旧名和改名的来龙去脉留在同一条里，旧文档不回头改。

当前常见句柄是 `L3`、`T5`、`L3:T5:S1`、`E123`、旧版 `J123` 和骨架 `k-…`。C 的程序接口已经存在，面向对话的导航尚未接入。只写稳定节点编号、动态展示路径的分层句柄方案仍属[后续设计](../engram/form/设计.md#分层索引设计方向)。
