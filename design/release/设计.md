# 公开发布

[← 索引](../INDEX.md)

## 公开材料

仓库提供程序、合成测试、提示词、宿主适配、项目设计与安装说明。实例配置、profile、个人内核、真实对话、运行数据和私有 Git 历史留在仓库之外。

设计按原项目的模块架构维护，公开版本保留概念、约束和实现边界，省去真实案例与个人部署细节。公开设计是经审阅的附属材料，不直接导出完整私有 `design/`：每篇登记它对应的原设计和审阅时的版本，原设计之后有改动，导出时提示复核，由人判断公开版要不要跟着改。

## 打包与清单

- `README.md` 与 `README.en.md` 是中英文项目介绍，设计入口为 `design/INDEX.md`。
- 通用安装配置在 `design/global/使用.md`，英文说明在 `使用.en.md`；具体用法跟随各模块。
- `MANIFEST.in` 将公开设计纳入源码包，运行时所需提示词、补丁和宿主资源由包配置提供。
- `RELEASE-MANIFEST.json` 记录公开文件的 SHA-256。改动文件与目录时同步更新清单，移除旧路径并校验新路径。

源码运行时，`design/` 可为本项目提供骨架和通用术语。个人内核与项目现状不随公开文档提供，资源选择见[实例配置](../global/使用.md#实例配置)。

## 导出检查

导出前把全部文件读入检查，一项不过就不写任何文件；报告只给「文件:行 类别」，不回显命中的内容。

- **个人标识、邮箱、凭据、机器路径、内网地址**：查全部文件。个人标识的名单不写死在代码里：除了兜底的固定名单，还现读实例配置里的称呼和别名、系统里的主机名、登录名、家目录名、版本管理里的用户名和邮箱，换机器、换用户不用改代码。邮箱和路径允许合成数据用的占位（example 域名、保留的 `.invalid`、`.test`，占位用户名）。
- **真实会话编号、指向私有材料的引用**：查文档。设计文档不应出现会话的真实编号，也不应指向公开仓库里没有的材料。
- **链接**：文档里的相对链接必须落在导出树内；锚点找不到作提示。
- **设计登记**：每篇公开设计都登记了对应的原设计；没登记的拦下。

清单哈希证明文件一致，不代替内容隐私审阅。

## 同步与验证

替换已有公开工作区前完整备份，保留公开仓库自己的 `.git`，不迁入私有提交历史。

- 先 `--dry-run` 看计划：会新增、改动、删除哪些文件。
- 导出树里没有、公开仓库里有的文件，同步会带走，所以有这样的文件时默认拒绝，要明确允许。设计和说明文档都在导出树里，正常同步不该有删除。
- 同步后，对公开仓库里新增的行和还没跟踪的新文件再检查一遍，有命中就先不提交。
- 提交与推送单独执行。
- 导出、公开测试、同步、同步后检查可以用一条命令串起来，最后列出相对公开仓库上次提交的改动后停下，任何一步没过就停；提交、打标签、推送不在其中。串起来时还会提示（不拦）两件事：版本号已有同名标签、这次却改了代码；介绍文档里出现读者查不到的内部编号。

源码包在临时目录构建，核对设计与宿主资源完整；测试使用 `python3 tools/test.py` 的合成数据与临时实例，不修改运行中的服务或记忆库。
