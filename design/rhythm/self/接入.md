# self 的宿主接入

[← self](设计.md) · 代码：[`mh/rhythm/self/hosts/`](../../../mh/rhythm/self/hosts)，一个宿主一个模块

上半是标准，所有宿主都照它；下半一个宿主一节，由在那个宿主里的“我”自己写、自己测：它最清楚自己的宿主。写完在“已接入”表里加一行。改标准本身（加一个函数、改一条要求），要在所有已接入的宿主上核一遍再落地。

## 要满足的

1. **醒来的就是“我”**：会话开始时有手记，能拉取（evoke、relive、roam、yorimichi），有联想；self 的 `AGENTS.md` 作为项目说明读进来。用这个宿主接 Synapse 的那一套（[Synapse“宿主接入”](../../synapse/设计.md)），不另起一套。
2. **不打扰用户**：不往用户的终端、通知、界面发信号，不改用户交互时用的配置；宿主自带的记忆关掉，记忆只用 mh。
3. **进记忆**：会话记录落在采集读得到的地方，工作区认成 self。采集读不到的，先给采集加一个来源（[observe 采集](../../engram/observe/采集.md)：一种来源一个解析器）。那一轮用户一侧的文字就是“此刻”文件的全文（便签 + 此刻），不被宿主包成别的样子：observe 按它认出自言自语，form 按它认出是哪张便签。
4. **读得到、写得到**：读得到用户家目录下的各个工作区；写 self 和草稿纸。别处由核心的只读沙箱拦（`confine.wrap`）：`launch` 把命令交给它包一层，传上宿主自己要写的路径（配置目录、登录凭据）。
5. **后台、能停、不用人批准**：不占终端，起在新的进程组里，超时整组停得掉；中间任何一步都不等人点头。
6. **续接能力**：宿主写明技术上能否续接、靠什么；能续接不代表缓存命中。当前核心每次新开会话，保留上一段指向，续接的成本策略另行验证。
7. **核查读得出**：从这次运行的记录里，读出它（含子代理）写了哪些文件、跑了哪些命令。读不出的在本节写明，核查会少一块。
8. **额度**：自己判断现在能不能叫（部署接了额度查询就看它），不能就说为什么。

## 要实现的

`mh/rhythm/self/hosts/<名字>.py`，在 `hosts/__init__.py` 的 `HOSTS` 里登记。便签头写 `host: <NAME>` 就由它来叫醒；不写是 `DEFAULT`（claude）；写了没登记的名字，算头里认不出的条件。

| 函数 | 做什么 |
|---|---|
| `NAME` | 便签头里认的名字，小写 |
| `MODEL` | 用这个宿主醒来时的模型；宿主 + 模型就是由“我”的哪部分醒来，核心记进状态和核查 |
| `ready()` | 空串 = 现在能叫；否则是为什么不能（额度吃紧、没装） |
| `new_session()` | 新会话的编号；宿主不能事先指定的返回 `""`，跑完由 `outcome` 读出来 |
| `resumable(session)` | 技术上是否能续接（记录还在、不太长）；不判断缓存或成本 |
| `launch(root, text, session, resumed, logs)` | 在后台起来，返回进程：cwd 是 `root`（self），输入是 `text` 文件，运行记录写进 `logs` 目录，新进程组 |
| `outcome(logs)` | `(正常结束没有, 最后一句, 会话编号)` |
| `actions(logs)` | `[("write", 路径) \| ("run", 命令)]`：这次会话（含子代理）自己做的 |

核心（`mh/rhythm/self/__init__.py`）负责其余的一切：判到点、挑哪张、建醒来的目录和草稿纸、写“此刻”、记续接、超时停、按 `actions` 核越界、写 `核查.md`、收尾提交。接入不碰这些。

## 怎么验

1. `mh.rhythm.self.test` 的 `test_hosts_contract` 查函数齐不齐。
2. 自己的单元测试：拿一份真实运行记录的样子，测 `actions`、`outcome` 读得对。
3. 冒烟：在临时目录里（临时的 self、临时配置目录、临时数据目录，会话不落进正式的采集目录），用便宜的模型叫醒两次。第一次：读到 AGENTS.md、能 evoke、写了醒来的目录和草稿纸、核查没越界。第二次：续接上一段，记得上一轮写了什么。再用采集的解析器解析这段会话：两轮，工作区认成 self。

## Claude Code

代码 [`hosts/claude.py`](../../../mh/rhythm/self/hosts/claude.py)。

- **怎么起**：`claude -p`，`--permission-mode dontAsk`，工具只给读写、Bash、子代理和 mh 的 MCP，`--output-format stream-json --verbose` 写进 `logs/run.jsonl`；环境变量 `CLAUDE_CONFIG_DIR` 指向独立的配置目录 `<数据目录>/claude-self-home`。
- **记忆（第 1、2 条）**：配置目录的 `settings.json` 每次照代码重写，只装 mh 自己的钩子（SessionStart 送手记，UserPromptSubmit 联想、开关、内核态，工具前后和 Stop 的内核态与开关），不装用户级的其它钩子；`autoMemoryEnabled: false`。MCP 用 `--mcp-config` 加 `--strict-mcp-config`，只有 mh。`--setting-sources user,project`：只给 `user` 时 self 的 AGENTS.md 读不进来。
- **进记忆（第 3 条）**：会话文件落在配置目录的 `projects/` 下，采集多读这一处（`observe/sources/claude.SELF_ROOT`）。
- **读写（第 4 条）**：`--add-dir ~` 读得到各个工作区；写由沙箱拦，可写的另加配置目录和登录凭据。
- **停（第 5 条）**：新进程组，超时由核心整组停掉。整理循环被服务管理器重启时，醒着的会话会跟着被停掉，那张便签隔一天再叫。
- **续接（第 6 条）**：新会话用 `--session-id` 事先指定，续接用 `--resume`；会话记录超过 `RESUME_BYTES`（3 MB）就另开一段；这是宿主能力，当前核心不自动续接。
- **核查（第 7 条）**：stream-json 里 assistant 消息的 `tool_use`（子代理的也在里面）：Write、Edit、MultiEdit、NotebookEdit 的路径算写，Bash 的命令算跑。
- **额度（第 8 条）**：部署接了额度查询（`mh/rhythm/quota.py`，公开包不带）时，Claude 的 5 小时窗口用到 `BUSY_5H` 就不叫；没接就当作不紧。

## Codex

代码 [`hosts/codex.py`](../../../mh/rhythm/self/hosts/codex.py)，按 Codex CLI 0.165.0 实测。

- **怎么起**：`codex exec --json -`，便签和“此刻”全文走 stdin；续接用 `codex exec resume <编号> ... -`。独立 `CODEX_HOME` 在 `<数据目录>/codex-self-home`，不复制交互配置，只链接认证。
- **记忆**：沿用 Synapse 的 Codex 手记、联想、MCP 绑定，补观察开关与内核态钩子；MCP 只有 mh。项目可信、原生读 AGENTS.md；生成的钩子用 `--dangerously-bypass-hook-trust` 在本次运行放行。关闭原生 memories 的生成和读取、插件、apps、更新检查和统计；不装通知钩子，不传外层会话号和 TMUX 身份。
- **进记忆**：会话保留在独立目录的 `sessions/`、`archived_sessions/`，采集复用 Codex 解析器多读这两处，工作区按 cwd 认成 self。
- **读写与停**：独立配置 `approval_policy = "never"`、`sandbox_mode = "danger-full-access"`，写入范围由核心的只读沙箱拦。新进程组，超时核心整组停。
- **续接**：新编号从 `thread.started` 读出；记录存在且小于 `RESUME_BYTES`（3 MB）时技术上可续接；当前核心每次新开，不自动续接。
- **核查**：读取实际命令、补丁事件，包括 exec 内部调用和按父会话关系递归找到的子代理。启动偏移与主轮结束时刻限定这一次；脚本内部写文件只能列命令。
- **额度**：没装、未登录不叫；部署有额度查询时按查询结果和 `BUSY_5H` 判断，未部署则由宿主报额度错误、核心隔天重试。
- **验证**：隔离目录里用便宜模型叫醒两次，手记、回忆、AGENTS.md、写入、续接、采集两轮与核查均通过；动作归属和轮次边界有单元测试。
