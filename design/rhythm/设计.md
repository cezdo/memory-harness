# rhythm

[← 设计索引](../INDEX.md) · 实现：[`mh/rhythm/`](../../mh/rhythm)

rhythm 按墙钟时间驱动过程，管理何时醒来、并行几个和可用额度。一批看什么、怎么看由各过程自己决定，例如会话多久算告一段落是 observe 的输入窗口参数。

## 当前三个循环

| 循环 | 一批做什么 | 隔离 |
|---|---|---|
| 观察 | 采集、预览、精读与粗读，再处理限量点名纠正 | `observe.lock` |
| 形成 | pack、label，再按时间顺序 attach | `form.lock` |
| 整理 | 到期的项目现状、检查、内部足迹与引用回填 | 独立循环及状态记录 |

```sh
python3 -m mh rhythm --once
python3 -m mh rhythm --form --once
python3 -m mh rhythm --tidy --once
```

去掉 `--once` 会持续运行；安装为宿主服务需要明确配置，见[使用说明](../global/使用.md)。这些命令不是测试命令，不应在验证文档时对真实实例执行。

观察与形成目前是独立进程，通过同一数据库交换数据，避免一段较慢的形成卡住采集。默认空闲轮询间隔为 5 分钟，但可以被叫醒：宿主一轮结束、有新的申请时叫醒观察循环，库里出现新的 E 或写给 form 的申请时叫醒形成循环。写申请的一方只管写库。一次批处理结束后释放写事务再休眠，不能拿着事务等下一批。

## 并发、额度与失败

模型调用可并行，数据库写入在受控的主线程。pack、label 可以并行，attach 需看到此前形成的线，保持时间顺序。新会话与范围再观察共用队列，不另设低优先级资源闸。

额度查询是只读操作（`mh quota`），预览模型池可按额度选择。读 Codex 额度的 app-server 有超时，到点记成读不到，不卡住观察循环。Claude 的额度接口按出口限流，读到的结果缓存十分钟，读不到时退回上次读到的并注明是多久以前。额度、限流、连接和服务未就绪等环境错误停止本批，稍后再试；内容错误的计数、待重做清单属于具体过程，不由节律猜测语义。

并发度、批次大小和超时是执行参数；影响模型所见输入的窗口规则计入 Operator，两者不混用。

## 常驻服务

三个循环各是一个用户级常驻服务（`memory-harness-observe`、`-form`、`-tidy`）。服务的定义只在 [`register.py`](../../mh/rhythm/register.py) 的 `SERVICES` 一份，按平台生成服务文件，不手写：

```sh
python3 -m mh rhythm --register           # 生成的和装着的差在哪
python3 -m mh rhythm --register --apply   # 写进去、登记开机自启；不重启正在跑的服务
```

Linux 上是 systemd 用户服务，macOS 上是 launchd 的 LaunchAgent，都只在非正常退出时拉起。远端调用的服务端 `memory-harness-invoke` 点名才生成，见 [observe](../engram/observe/设计.md)。

## 整理循环

维护读的一侧工作集，让手记跟上项目与记忆的实际状态。任务登记自己的周期与成本类型，循环定期唤醒，到期各跑一次；单个任务失败不阻挡其他任务，上次运行时间存入私有状态文件。

项目现状与检查是程序任务，引用回填可以调用模型；每天一次的待办清单更新稿也调模型，清单和提交都没变就不调，稿只进数据目录、不改仓库，由在场时的会话看过再改。周期随成本确定，不把所有任务都变成每轮模型调用。项目现状的编写规则归 Synapse，节律只负责叫醒。
