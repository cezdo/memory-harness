# Synapse

[← 设计索引](../INDEX.md) · 实现：[`mh/synapse/`](../../mh/synapse)

Synapse 让已有认识参与现在，也让助手知道还有什么可查。它只读 Claim，只追加 use。对话与 Engram 内部过程的拉取都保留来源与读取足迹。

## 结构

| 部分 | 职责 |
|---|---|
| `hosts/` | Claude Code、Codex、dsh 的接入与上下文识别 |
| `push/` | 手记、内核态、“没印象”提示、联想候选 |
| `pull/` | evoke、relive、roam，检索与 MCP 服务 |
| `track/` | use、访问树、引用回填和呈现反馈 |

## 手记

会话接入时送一次（新会话、恢复、清空、压缩之后），按稳定到易变的顺序送入四块：扉页（内核 `core.md`）、工具用途与句柄说明、近况（项目现状）、当前环境，分别是 `# 手记` 下的“扉页”“近况”“环境”几节。叫手记，是因为它读了会当作自己相信的经历、记不太住时重读的那份；不用“开场”“开机”这类会话开关的说法，目标是无感切换会话。整个返回文本包在 `<memory-harness use="…">…</memory-harness>` 中。每次送出记一条 use，正文里写出的话题和所在的线都记成送达，工具说明里的示例句柄不算。

扉页保存每次接入都需要、不能仅靠程序保证的稳定内容，几乎不改；近况保存最近进度；仓库做事规则由宿主自己的文档加载机制承担。内核和项目现状从实例配置指定的私有资源读取，缺失时对应部分省略；通用词典的源码默认来源见 [form](../engram/form/设计.md#骨架)。公共设计文档不填充个人内核。

近况（项目现状）由整理循环事先编好，包含目录活动、提交与未提交文件、服务异常、检查变化，以及最近停下的会话。未提交的改动按会话标出是谁碰的：每个文件归给改动时刻之前、近几天里最后碰过它的会话（看工具调用里的路径，相对路径按命令里的目录展开），在别处开的会话标明在哪开的。最近停下的会话已有话题的用句柄接回，还未形成的保留宿主会话线索；在别的工作区开、却碰过本工作区路径的会话也会列出。近况只读缓存，当前会话排除；用户点名后再拉取具体历史。

宿主已提供的 Git 信息可以省略，异常比正常明细优先。项目现状是缓存快照，不能当作实时健康检查。`mh boot` 可预览当前工作区的手记，旧命令 `mh standing` 仍可用。

## 内核态

内核默认只读。用户以专用命令开启一轮编辑窗口，钩子记录授权，轮次结束、下一次输入或超时后关闭。编辑类工具在窗口外修改内核时被拒绝，工具调用后再比对文件快照并追加 diff 日志。

日志区分授权内编辑与后来发现的未登记改动。发现者不等于修改者，不把检测到改动的宿主和会话当成作者。

这是一条工具路径上的约束和审计机制：shell 命令不作完整解析，钩子错误会放行并记日志，因此不是覆盖所有写入方式的文件系统权限隔离。

安装内核态的命令与钩子需显式执行，先预览：

```sh
python3 -m mh.synapse.push.elevate
python3 -m mh.synapse.push.elevate --apply
```

安装器为 Claude Code 和 Codex 添加命令或 skill 及钩子；Codex 新钩子需在 `/hooks` 中信任。Claude Code 使用 `/mhcore <要求>`，Codex 使用 `$mhcore <要求>`。日志在 `$MH_HOME/kernel-log.jsonl`。Claude Code 的授权与拦截已有实测；Codex 的宿主拦截仍需实际验证，dsh 尚未接入。钩子错误时放行并记录，不能据此承诺完整的写入隔离。

`[resources].core` 未指定时，从实例配置旁读取 `core.md`，兼容旧的 `standing` 配置与 `standing.md`。公开仓库不提供个人内核文件。

## 中途推送

“没印象”提示针对用户输入中足够特别、当前记忆找不到的词。程序结合词性、当前记录、通用词库、语言规则和实例静默词表过滤；同一会话同一词只在实际送达后去重。找不到只说明记忆中缺少该词，不能据此判断外部对象不存在。

逐轮联想目前暂停送达。候选、门槛和原本会推的内容继续记录，但这些记录不能算成曝光。联想下一步要解决的是跨长链路的回想，而不只是字面词巧合；采用即时推荐还是先形成新认识，仍待验证。

## 三种拉取

| 工具 | 参数方向 | 行为 |
|---|---|---|
| `evoke` | 几个查询词 | 按相关度找线、话题、骨架和陈述，命中给正文 |
| `relive` | 一个或多个句柄 | 按位置和结构读，可展开来源、原话与历史 |
| `roam` | 工作区或节点，可空 | 列工作区或读下一层，适合不知道查询词时 |

三个工具支持可选意见 `note`。`evoke` 一页给 6–8 条（至少 6 条，字数够再加到 8 条，超过约 800 字就停），话题线和陈述各先占一半，一路不够让给另一路；同一轮里前面给过的不再列，所以同一轮再 evoke 同样的词就是接着往下看，页脚附上“不去重时本该出现在这一页”的句柄。一轮从这段会话最近一次联想推送算起。`relive`、`roam` 每页固定 8 条，不能调大，只用 `page` 翻页；截断提供继续读的提示。`evoke` 的 `grain` 控制最细结果到线、话题还是陈述。

查看窗口的原则：看任何内容都遵从 6–8 条的窗口。层级先用现成的结构（写入时已付过的预览分组、物理的轮和段落、子线），零开支；没有现成结构的排好序就翻页，冷门的多查几次；热门的（被反复打开又总超窗）才按足迹调模型建索引直达，开支跟着使用增长、不跟着数据增长。不在写入时给所有内容预先造层级。

`relive` 不重新按相关度挑选：陈述带相邻上下文，话题按原顺序读，线与骨架给下一层；`source` 追依据，`said` 到原话，`files` 看陈述里的文件指向，`recall` 看历史。名字必须逐字匹配且唯一。旧 J 仍能按句柄回溯，标为退役，不进入当前 evoke。

话题的陈述在一页以内时从头按顺序读；超出一页先给目录：陈述按 observe 预览的分组归节，一节一行，写第几轮、预览的类型和这一节的句柄，读一节就是 relive 那个句柄；对不上预览的旧做法观察，归“其余”，全对不上就照旧按顺序读。预览的分组是写入时已经付过的，不另调模型。

陈述的来源按页对齐分节：一页以内照常给；form 写下了结构的（直接来源、各引用、各文件）按结构分，一节一个；没有结构的旧陈述按预览组分节，再按窗口切齐。分了节的，同一轮里再执行一次同样的 relive 给下一节，给完说一共几节。来源默认只给直接来源和引用，只出现在文件指向里的不给，`files` 才给；`said` 对每段原话只给位置和开头，同一段只给一次，要全文就 relive 那条事件。话题的最后一次挂线还标着“待审视”（晚到的事件落进已整理的范围）时，话题头下面多一行提示，主会话看过后用反馈改挂（挂到同一条线也行），标记随新的挂线清掉。

完整的分层方案要求稳定编号与展示路径分开，evoke 带路径、relive 和 roam 每次一层；尚未完整落地，见 [form](../engram/form/设计.md#分层索引设计方向)。

## 共用检索

form 起名、挂线与交互 evoke 复用 [`retrieve.py`](../../mh/synapse/pull/retrieve.py)，纯程序执行：

- **索引词匹配**按名字、别名及必要的相邻和不单独约束命中。
- **BM25**用 ASCII 词与汉字二元组处理入口文档和陈述，不依赖外部分词器。
- 两路各取候选后合并，不硬混成一个分数。
- 在工作区中过于常见的“大词”不单独触发；几乎处处出现的词也从 BM25 查询中排除。
- 别名主要在形成入口时补齐，查询不把缺失内容伪装成“没选好词”。

语义向量不是当前检索的必需组件。工作区映射分别用于采集侧和推送侧，尚未完全统一，实例配置应明确其边界。

## 足迹与证据

每次推送、拉取和导航保存 use：会话、目的、版本、查询、返回的哪些记录及其版本、意见和实际送达文本。交互、预取、离线回放、开发调用和内部 form/cognize 拉取分别标记，分析时决定哪些算真实使用。

曝光是给到了什么，在场是回复时仍在上下文，有回应是后续拉取、引用或复述。当前引用回填的候选仍主要按曝光计算，尚未完全按压缩边界收窄，不能把它写成精确的“在场”证据。

访问树从 use 推出读取路径：此前曝光的句柄被展开时，连接到最近给出它的步骤；否则成为新根。程序统计深度、步数和跨轮路径，不声称知道模型是否读懂。

引用回填先用字面检索找候选，再在同一个问题中选一条或“都不是”，避免逐条问相似主题时都被肯定。连接结果作为新的足迹保留。〖〗里直接写了句柄（线、话题或陈述的句柄）的，由程序解析后直接连上，不看曝光、不问模型；去掉句柄后剩下的正文还够长，再按上面的办法认一遍。完整的“错过”“误导”和“一起被需要”分析仍在后续设计中。

## MCP、反馈与宿主

MCP 服务使用 stdio JSON-RPC，按 schema 校验参数。记录反馈转交 Engram，呈现反馈引用 use 追加记录，见[修正机制](../engram/申请.md)。

三个宿主共用核心推送和拉取入口，各自适配消息封装、上下文、会话标识与生命周期。会话标识会变：Claude Code 清空或恢复之后宿主换了会话，MCP 子进程不重启，环境变量里的编号还是启动时的，所以接入钩子把当前会话登记在数据目录里，MCP 按父进程读取，读不到才退回环境变量；以前记错会话的足迹不改原记录，追加一条更正，按会话读足迹的地方认更正。Codex 的 MCP 调用由宿主钩子补充会话和工作目录；dsh 使用插件接入。安装、服务启动及重启都由明确操作完成，测试不替用户安装。

修改调用入口时同步更新打包提示词、补丁和宿主资源。用临时配置与合成会话验证，真实宿主事件另行验证，不以静态配置代替运行证据。

## 使用与宿主接入

```sh
mh evoke 关键词
mh roam
mh relive L3:T5 --said
```

清空的线不再列入检索与地图，旧句柄仍可打开并追后继。MCP 参数名写错或缺少必填项时，返回具体错误与可用参数说明。

MCP 服务入口：

```sh
python3 -m mh.synapse.pull.mcp
```

该进程使用标准输入输出。宿主配置应给出正确的 Python、代码路径与实例环境变量。Codex 安装器可先通过 `python3 -m mh.synapse.hosts.codex.install --help` 查看，它修改用户级配置，需显式执行安装。

Claude Code 的手记钩子是 `python3 -m mh inject`，逐轮钩子是 `python3 -m mh.synapse.push.associate`。dsh 插件在 [`hosts/dsh/`](../../mh/synapse/hosts/dsh/)，按宿主插件配置加载。改变入口后需要重启对应宿主验证实际事件。

### 可选依赖

“没印象”提示与联想候选使用 LTP 和可选通用词库，由 `MH_LTP_PYTHON`、`MH_LTP_MODEL`、`MH_LEXICON` 指定。工具、模型权重与词库需自行准备，默认路径见[使用说明](../global/使用.md)。

引用回填 `mh backfill` 需要 TypeSafe SDK，辅助 Python 用 `MH_TYPESAFE_PYTHON` 指定；凭据文件为 `~/.config/memory-harness/typesafe.env`，包含 `TYPESAFE_API_KEY`，可选 `TYPESAFE_MODEL`。密钥与回填结果不进入仓库。
