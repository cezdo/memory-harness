# Synapse

[← 设计索引](../INDEX.md) · 实现：[`mh/synapse/`](../../mh/synapse)

Synapse 让已有认识参与现在，也让助手知道还有什么可查。它只读 Claim，只追加 use：它不改变“有什么”，只改变“哪些 Claim 此刻在场”。它产出的都是 Occurrence：use（送了什么、读了什么）、写给 Engram 的申请，以及状态变化（联想开关、yorimichi、提权）。

## 结构

按功能分，每个功能内部都是一次 S→R→P：接收宿主事件，决定哪些 Claim 现在该参与、给多少，再排版送出并记下送了什么。

| 功能 | 管什么 | 什么时候 |
|---|---|---|
| 手记 | 扉页（内核）、工具说明、近况、环境 | 会话开始 |
| 每一轮 | “没印象”提示；联想 | 用户每说一句 |
| 拉取 | evoke、relive、roam、检索、反馈 | 助手主动；form 起名、挂线也用 |
| 内核态 | 内核的提权、拦截与日志 | 用户 `/mhcore` |
| 足迹 | use、访问树、引用回填 | 事后 |
| 宿主接入 | Claude Code、Codex、dsh 的适配；MCP 服务 | 一直 |

## 手记

会话接入时送一次（新会话、恢复、清空、压缩之后），按稳定到易变的顺序：扉页（内核 `core.md`）、工具与句柄说明、近况、当前环境，包在 `<memory-harness use="…">…</memory-harness>` 中。叫手记，是因为助手读了会当作自己相信的经历、记不太住时重读的那份；目标是无感地切换会话。每次送出记一条 use。

扉页是每次接入都需要的稳定内容，几乎不改；内核和近况从实例配置指定的私有资源读取，缺失时省略，公开仓库不提供个人内核。仓库的做事规则由宿主自己的文档机制加载。

近况由整理循环事先编好，只推异常：目录活动、最近提交、未提交的改动及是哪段会话碰的、服务异常、和上一次相比变了的检查项、最近停下的几段会话（已形成的给句柄，用户点名再拉取）。登记了待办清单的工作区，还推清单里落后、和设计对不上的地方，以及模型每天写的一份更新稿的提示；稿由在场的会话看过再改，不直接改仓库。近况是缓存快照，不是实时健康检查。`mh boot` 预览当前工作区的手记。

## 每一轮

**“没印象”提示**：用户输入里足够特别、记忆中逐字找不到的名词，提示一句，免得助手把“记忆里没有”和“外面不存在”混为一谈。程序按词性、通用词库、词典词头和实例的静默词表过滤；一个词说过一次就不再说。

**联想**：程序在陈述里找和这句话相关的内容，不调模型，按话题归并送出（第一行 `[Souhatsu]`，每个话题带句柄和一条命中片段）。送多少由 **yorimichi** 定：助手在对话阶段变了时用 MCP 工具 `yorimichi` 记下允许拐几次，0 是在一个点上深挖、不送，1–3 送这么多个话题；没记过是 0。用户的 `/no-souhatsu`、`/do-souhatsu`（Codex 写 `$`）关掉或恢复这个会话的联想，优先于 yorimichi，“没印象”照旧。不送的候选照样记录，但不算曝光。dsh 还没接联想开关。

## 拉取

| 工具 | 参数 | 行为 |
|---|---|---|
| `evoke` | 几个查询词 | 按相关度找线、话题、骨架和陈述，命中给正文 |
| `relive` | 一个或多个句柄 | 按位置和结构读，可展开来源、原话与历史 |
| `roam` | 工作区或节点，可空 | 一层层走，适合不知道查询词时 |

看任何内容都守 6–8 条的窗口：`evoke` 一页 6–8 条，同一轮再查同样的词就是接着往下；`relive`、`roam` 一页 8 条，只能翻页。层级先用写入时已有的结构（预览分组、轮、子线），长话题先给目录、来源按页分节，不在写入时为所有内容预先造层级。`relive` 不重新按相关度挑选，旧版 J 能按句柄回溯但不进 evoke。完整的分层句柄方案尚未落地，见 [form](../engram/form/设计.md#分层索引设计方向)。

form 起名、挂线和 evoke 共用 [`retrieve.py`](../../mh/synapse/pull/retrieve.py)，纯程序：索引词匹配和 BM25（ASCII 词加汉字二元组）两路各取候选再合并；工作区里过于常见的词不单独触发。语义向量不是必需组件。

## 内核态

内核默认只读。用户以 `/mhcore <要求>`（Codex 写 `$mhcore`）开一轮编辑窗口，这一轮结束、下一次输入或超时后关闭。编辑类工具在窗口外改内核会被拒绝；每次工具调用后比对快照，改动追加进 `$MH_HOME/kernel-log.jsonl`，窗口外发现的标为未登记（发现者不等于修改者）。日志可照 dmesg 一条一行地读：`python3 -m mh.synapse.push.elevate log`。

这是工具路径上的约束和审计，不是文件系统权限隔离：shell 命令不完整解析，钩子出错时放行并记录。dsh 尚未接入。安装先预览再执行：

```sh
python3 -m mh.synapse.push.elevate
python3 -m mh.synapse.push.elevate --apply
```

## 足迹

每次推送、拉取和导航保存 use：会话、目的、版本、查询、返回了哪些记录和实际送达的文本；交互、预取、回放、开发和内部拉取分别标记。曝光是给到了什么，在场是回复时仍在上下文，有回应是后续的拉取、引用或复述；“用上了”“读懂了”不由模型自评。

访问树从 use 推出读取路径。引用回填把助手正文里〖〗标出的记忆连回陈述：写了句柄的由程序直接连，没写的先字面检索候选，再让模型在一个问题里选一条或“都不是”。

## 宿主接入

三个宿主共用同一套入口，各自适配消息封装、会话标识和生命周期：Claude Code 用钩子（手记 `python3 -m mh inject`，每一轮 `python3 -m mh.synapse.push.associate`）；Codex 用安装器写入钩子和 MCP 配置（`python3 -m mh.synapse.hosts.codex.install --help`），新钩子需在 `/hooks` 里信任；dsh 用 [`hosts/dsh/`](../../mh/synapse/hosts/dsh/) 的插件。会话标识会在清空、恢复后改变，接入钩子把当前会话登记在数据目录，MCP 按父进程读取。

MCP 服务是 stdio JSON-RPC（`python3 -m mh.synapse.pull.mcp`），工具有 `evoke`、`relive`、`roam`、`feedback`、`yorimichi` 和 `observe-now`（实现在 [observe](../engram/observe/设计.md)），按 schema 校验参数，写错时返回具体错误与参数表。记录反馈转交 Engram，见[修正机制](../engram/申请.md)。安装、启动、重启都由明确操作完成；改了入口要重启宿主、用真实事件验证。

```sh
mh evoke 关键词
mh roam
mh relive L3:T5 --said
```

### 可选依赖

“没印象”提示与联想使用 LTP 和可选通用词库，由 `MH_LTP_PYTHON`、`MH_LTP_MODEL`、`MH_LEXICON` 指定，需自行准备，默认路径见[使用说明](../global/使用.md)。引用回填 `mh backfill` 需要 TypeSafe SDK（`MH_TYPESAFE_PYTHON`），凭据在 `~/.config/memory-harness/typesafe.env`（`TYPESAFE_API_KEY`，可选 `TYPESAFE_MODEL`）。
