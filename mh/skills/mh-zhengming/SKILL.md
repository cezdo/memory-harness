# 正名（mh-zhengming 0.1）

要做的：$ARGUMENTS（没替换成内容的，看用户消息；再没有就看这段对话里刚定下或改掉的名字）。

名不正则言不顺：同一个词指两样东西，或者名字和现状对不上，讨论就会在不知不觉中偏掉。正名留下的产物是词典。

词典和目录设计一起是工作区的骨架：目录说有哪些部分，词典说每个部分里的东西叫什么、指什么、为什么这么叫。接手一块的人只读那一节就明白一大截。所以它要短、准、跟得上现状。

## 先找到这个工作区的词典

- 实例配置（`~/.config/memory-harness/instance.toml`）里给了这个工作区的词典位置，就用那里；没有就看工作区里有没有现成的（`docs/词典.md`、`design/global/词典.md`、`GLOSSARY.md` 之类）。
- 都没有：问用户放在哪（工作区里的一个文件，还是不进工作区）。不擅自往用户的仓库里加文件。
- 词典放在要推送的仓库里：人名写“用户”，不收私人账户、口令。

## 三件事，按要做的挑一件

### 起草（工作区还没有词典）

1. 先看目录：工作区的目录结构和 README、设计文档的标题，定下分节——词典按目录分节，接手哪块读哪节。
2. 列候选：从记忆里找这个工作区的叫法（mcp__mh__evoke 用工作区名和主要模块名查，mcp__mh__relive 读下去）；陈述里「」括的专名、反引号里的标识符、目录和命令名都是候选。出现两次以上的优先。
3. 每个候选看几条出处，判收不收（见下面“收什么”），收的写一条。同一个东西的几种写法合成一条。
4. 交用户核对：列出拿不准的（指代是推出来的、两条可能是一回事），其余整份给用户在工作区里自己看。起草时看的出处不写进词典。

### 记一笔（一件事里定了名、改了名）

- 新名字：在它所属的那一节加一条，至少写指代。
- 改了名：在原来那条的词头把现名放到最前、旧名跟在后面，在“改名与取代”里追加一句（什么时候、为什么改）；不删旧名，不回头改旧文档。
- 碰到同一个词指两样东西，或一样东西有两个名字还没定用哪个：记进末尾的“撞名与未定”，解决前不硬改。

### 核对（定期，或用户要求）

- 挑出：新加还没核过的；和现状对不上的（目录、代码、设计里已经没有了，或做法变了而指代没跟上）。
- 一次问几条，问法照实、不给压力：“这条我写的是……，对吗？”用户的修正照“只追加”写进去，核过的可以记下日期。
- 发现过时就改：词典写的是现在的认识，读的人会照着它答。

## 一条怎么写

- **收**：这个工作区里会被反复用到的叫法——模块、概念、功能、命令、约定，用户自己的说法。行业通用名词只在这里有特定用法时收，指代写它在这里的用法。
- **不收**：条目编号（待办里的 F1、清单里的 OUT-04）、版本号、提交号、一次性的名字、别的工作区的东西。
- **词头**：`**现名 / 旧名 / 简称**`。“/”只连同一个东西的几种叫法（大小写、简称都算），现名在前；“、”并列不同的东西；“；”分开相关但不同的；括号里只放说明。
- **字段**：
  - 指代（必写）：在这个工作区里指什么，一两句。
  - 含义、来历：帮得上忙时写（为什么要有它、在什么情况下定下来）。
  - 改名与取代：改过名才写，只追加。
  - 定名方式：可选，只在有意义时写（用户定、讨论后定、“我”提出未确认）。
- **改名还是别名**：旧名从此不再用，才算改名；几个名字一直并存、只是哪个当主名变了，是别名——那次变化是一件事，不是叫法的变化。
- 不挂句柄、不写来源编号：词典本身就是核对过的、比记忆更高一级的句柄。

## 自检

- 只读这一节，没有别的上下文，能说出这块里有什么、各叫什么吗？
- 有没有收了编号、版本号、一次性的名字？有没有私人的东西进了要推送的文件？
- 每条的指代是现在的样子吗？改过的名字，旧名还在词头里吗？
